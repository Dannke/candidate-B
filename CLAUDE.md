# Отчёт по расчётам с подрядчиками

## Цель

CLI на Python: по файлам из `data/` и дате строит отчёт —
по каждой работе «цена / выплачено / осталось оплатить», по каждому договору итоги.
Читает отчёт бухгалтер, а не программист: русские подписи, никаких технических терминов в выводе.

Что сдаём: `report.py`, `test_report.py`, `README.md` (как запустить), `DECISIONS.md`,
`NOTE.md` (записка бухгалтеру), экспорт сессий `/export`.

## Команды

```
python report.py --date 2026-11-10     # отчёт в консоль
python -m unittest -v                  # тесты
```

## Жёсткие правила

- Только стандартная библиотека Python 3.10+ (`csv`, `decimal`, `datetime`, `unittest`; без `argparse` — см. `DECISIONS.md`, запись 12).
  Никаких `pip install`, БД, docker, веб-интерфейса, HTTP-сервера.
- Деньги — `Decimal`, созданный из строки CSV. Никогда `float`, никогда `Decimal(float)`.
  В расчёте только сложение, вычитание и `min` — деления и округления быть не должно.
  Если понадобилось делить — остановись, это признак смены правила распределения.
- `data/` только читаем. Данные не правим, даже если в них видна ошибка, — пишем о ней в отчёте и в `DECISIONS.md`.
- Колонка `status` в CSV — состояние на момент выгрузки, а не на дату отчёта.
  Состояние на дату выводим только из дат (`paid_at`, `refunded_at`, `completed_at`, `cancelled_at`).
- Ничего не додумываем молча. Данных не хватает или они противоречат друг другу —
  сначала запись в `DECISIONS.md`, потом тест, потом код. Бухгалтер недоступен, спросить некого.
- Плохие данные (неизвестный договор или работа, неизвестный статус, `paid` без `paid_at`,
  сумма с минусом или больше чем с двумя знаками) — остановка с сообщением «файл, строка, что не так». Строки молча не пропускаем.
- Минимум кода: один файл с расчётом, без классов-обёрток, конфигов и опций «на будущее».

## Состояние на дату D (включительно)

- Платёж выплачен: `paid_at <= D` и (`refunded_at` пусто или `refunded_at > D`).
  `queued` не имеет `paid_at` — значит не выплачен.
- Работа принята: `completed_at <= D`. Отменена: `cancelled_at <= D`. Иначе — запланирована.
- Договор участвует в отчёте, если `signed_at <= D`.

## Распределение платежей по работам

Источник правды — `DECISIONS.md`. Сейчас принято:

1. Привязанный платёж идёт своей работе, но не больше её цены.
   Излишек и платежи, привязанные к отменённой работе, уходят в общий остаток договора.
2. Общий остаток (непривязанные платежи + излишки) гасит работы по очереди, каждую до полной цены:
   сначала принятые — по дате приёмки, затем запланированные — по номеру работы. Отменённые пропускаем.
3. Что осталось после всех работ — строка «Переплата / нераспределено» в итогах договора.
   Остаток к оплате в минус не уходит.

## Инварианты (каждый — тест)

- По договору: сумма «выплачено» по работам + «нераспределено» = сумма платежей, выплаченных на дату.
- По работе: `0 <= выплачено <= цена`; `осталось = цена - выплачено`; у отменённой «осталось» = 0.
- Итог договора = сумма строк его неотменённых работ, до копейки.

## Устройство кода

`загрузка и проверка CSV -> состояние на дату -> распределение -> печать`.
Расчёт — чистые функции без печати и чтения файлов, чтобы тестировать их на данных в памяти.
Печать: `sys.stdout.reconfigure(encoding="utf-8")` — иначе консоль Windows сломает кавычки «».

## Формат записи в DECISIONS.md

> **Название.** Варианты: … Выбрал: … потому что … Если неверно: что изменится в отчёте.

## Сессия

Вся работа сдаётся экспортом `/export` без правок. Не выводить секреты в чат,
не делать `/clear` до экспорта, каждую сессию экспортировать отдельно.
